# /diagnose — Deep Diagnostic for Failing or Stuck Operations

## Purpose
Perform a comprehensive root-cause analysis of any enterprise, programme, or initiative that exists but isn't working. Goes beyond symptoms to find the structural reasons why something is failing — and produces a specific turnaround prescription.

## Trigger
User says: /diagnose [description of what's going wrong]

## What This Skill Solves
- **Revenue declining but owner doesn't know why** — could be market, competition, operations, pricing, or all four
- **Programme launched but not delivering** — government or NGO initiative that stalled
- **Business surviving but not growing** — stuck at subsistence level
- **Cooperative formed but not functioning** — governance, trust, or market failures
- **Good idea, poor execution** — the concept works but the implementation doesn't

## Input Required
ONE sentence minimum. Examples:
- "My restaurant has fewer customers every month"
- "The cooperative hasn't sold anything in 6 months"
- "The government training programme has 80% dropout"
- "My shop makes sales but I'm always broke"

## Diagnostic Framework

Month 4: ___  Month 5: ___  Month 6: ___

Revenue Sources:
Source 1: ___________  Share: ___% Reliable? Y/N

DANGER FLAGS:
□ Single customer >50% of revenue
□ Revenue depends on one product/service
□ Seasonal with no off-season plan

  Rent: ___  Salaries: ___  Utilities: ___  Loan payments: ___

  Are meetings held regularly? □ Yes  □ No  Frequency: ___
  Are financial reports shared with members? □ Yes  □ No
  Has there been any dispute about money? □ Yes  □ No

## ROOT CAUSE ANALYSIS

After completing all 6 layers, identify:

```
ROOT CAUSE REPORT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

PRIMARY ROOT CAUSE (the #1 reason this is failing):
_________________________________________________

CONTRIBUTING CAUSES (making the primary cause worse):
1. _______________________________________________
2. _______________________________________________
3. _______________________________________________

SYMPTOMS vs CAUSES:
  The owner thinks the problem is: _______________
  The actual problem is: ________________________
  (These are often different)

SEVERITY ASSESSMENT:
  □ CRITICAL — Will fail within 3 months without intervention
  □ SERIOUS — Declining but has 6-12 months of runway
  □ MODERATE — Stuck but stable, not getting worse
  □ MILD — Fundamentally sound, needs specific fixes
```

```

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

IMMEDIATE (This Week):
  Action 1: ___  Owner: ___  Expected result: ___
  Action 2: ___  Owner: ___  Expected result: ___
  Action 3: ___  Owner: ___  Expected result: ___

SHORT-TERM (Next 30 Days):
  Action 1: ___  Owner: ___  Expected result: ___
  Action 2: ___  Owner: ___  Expected result: ___
  Action 3: ___  Owner: ___  Expected result: ___

MEDIUM-TERM (Next 90 Days):
  Action 1: ___  Owner: ___  Expected result: ___
  Action 2: ___  Owner: ___  Expected result: ___

SKILLS TO DEPLOY NEXT:
  → /business-rescue (if turnaround needed)
  → /financial-model (if revenue model must be redesigned)
  → /supply-chain (if operations are the root cause)
  → /stakeholder-map (if politics/corruption is blocking)
  → /execute (always — for daily tracking)

HONEST VERDICT:
  □ SAVEABLE — with the above actions, this can be turned around
  □ PIVOT NEEDED — the current model won't work, but the assets
    can be redirected to something viable
  □ WIND DOWN — the honest advice is to close gracefully, preserve
    assets, and start something new using /solve
```

## Output Format
Deliver the complete diagnostic with root cause analysis and prescription. Be honest — if the business should close, say so. False hope wastes money and time. Always end with specific next skills to deploy.

## Connects To
- `/business-rescue` — full turnaround plan after diagnosis
- `/financial-model` — redesigned financial structure
- `/supply-chain` — operational overhaul
- `/stakeholder-map` — if governance or politics is the root cause
- `/execute` — daily tracking for the turnaround
- `/health-check` — lighter version for quick assessment
